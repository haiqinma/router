# 路由架构 V4

版本：`规划中`
状态：方向草案

V4 建立在 [路由架构 V3](./路由架构V3.md) 完成采购事实、请求成本归因、利润状态和基础下钻闭环之后。

V4 不继续向三个一级页面堆叠信息，而是建设对象化财务详情、跨周期分析和辅助决策能力。

## 1. 版本目标

V4 需要回答：

1. 某个渠道、模型、日期或异常为什么产生当前财务结果？
2. 财务结果相对上一周期发生了什么变化？
3. 哪些问题需要优先处理，处理后产生了什么效果？
4. 当前售价、渠道选择和采购计划应该如何调整？

V4 的核心方向：

```text
从页面级下钻
升级为对象级分析
再升级为辅助决策
```

## 2. 对象化详情路由

V4 可以新增以下详情路由：

```text
/admin/finance/overview/channels/:channel_id
/admin/finance/overview/models/:model
/admin/finance/overview/days/:date
/admin/finance/overview/issues/:issue_type
/admin/finance/profit/models/:model
/admin/finance/profit/channels/:channel_id
```

详情路由必须继承：

- 时间范围。
- 分组范围。
- 渠道范围。
- 模型范围。
- 基础币种。
- 返回来源。

## 3. 渠道财务详情

渠道详情展示：

1. 请求数。
2. 计费收入。
3. 采购成本。
4. 毛利和毛利率。
5. 成本覆盖率。
6. 关联模型利润分布。
7. 成本来源分布。
8. 采购批次使用摘要。
9. 主要异常。
10. 收入、成本和利润趋势。

渠道详情 Action：

- 查看渠道利润。
- 管理渠道采购。
- 查看关联模型。
- 查看请求日志。
- 检查渠道路由优先级。

## 4. 模型财务详情

模型详情需要比较同一模型在不同渠道下的经营表现：

| 字段 | 说明 |
| --- | --- |
| 渠道 | 实际承载请求的渠道 |
| 请求数 | 当前范围内请求量 |
| 计费收入 | 用户侧结算收入 |
| 采购成本 | 已归因上游成本 |
| 毛利率 | 渠道维度模型毛利率 |
| 成本覆盖 | 正式成本请求比例 |
| 路由占比 | 该渠道承载该模型请求的比例 |

模型详情需要帮助判断：

1. 哪个渠道导致亏损。
2. 哪个渠道成本缺失。
3. 哪个渠道利润和稳定性更好。
4. 是否需要调整价格、倍率或路由顺序。

## 5. 日期财务详情

趋势中的日期支持下钻，展示：

1. 当日收入、成本、毛利和毛利率。
2. 相对前一日和上一周期的变化。
3. 变化最大的模型。
4. 变化最大的渠道。
5. 新出现和已恢复的异常。
6. 成本覆盖率变化原因。

日期详情用于解释波动来源，不承担采购编辑。

## 6. 财务异常中心

V4 将异常从总览提示升级为可追踪对象。

异常对象字段：

1. 异常 ID。
2. 异常类型。
3. 严重程度。
4. 影响对象类型和 ID。
5. 影响请求数和金额。
6. 首次出现时间。
7. 最近出现时间。
8. 当前状态。
9. 推荐动作。
10. 处理人和处理记录。
11. 恢复时间和恢复依据。

异常状态：

```text
open
acknowledged
processing
resolved
ignored
```

异常中心需要支持：

- 按类型、严重程度、对象和状态筛选。
- 从异常进入利润、采购或日志。
- 记录处理动作。
- 判断问题是否恢复。
- 对重复异常进行聚合和去重。

## 7. 周期对比

V4 增加标准周期对比：

- 当前 7 天对比前 7 天。
- 当前月对比上月。
- 自定义范围对比等长前置范围。

对比指标：

1. 计费收入变化。
2. 采购成本变化。
3. 毛利变化。
4. 毛利率变化。
5. 成本覆盖变化。
6. 模型和渠道贡献变化。
7. 异常数量变化。

变化必须能够继续下钻到贡献对象，不能只展示百分比。

## 8. 导出与共享

V4 可以提供：

1. 导出当前统计范围的财务摘要。
2. 导出模型和渠道利润明细。
3. 导出成本覆盖和异常明细。
4. 复制包含完整筛选上下文的链接。
5. 生成只读财务快照用于阶段复盘。

导出必须带上：

- 时间范围。
- 筛选条件。
- 币种。
- 数据生成时间。
- 成本口径和覆盖率。

## 9. 辅助决策

V4 可以在数据可信后提供建议，但默认不自动执行。

建议类型：

1. 售价低于成本底线，建议检查价格。
2. 毛利率低于目标，建议调整倍率或售价。
3. 某渠道成本明显高于同模型其他渠道，建议检查路由优先级。
4. 采购容量即将耗尽，建议补量或续费。
5. 采购资源长期闲置，建议减少采购或调整路由。
6. 成本覆盖持续下降，建议补齐采购事实。

所有建议必须展示：

- 使用的数据范围。
- 判断依据。
- 预期影响。
- 数据可信度。
- 需要人工确认的 Action。

## 10. 预测能力

在采购事件、批次消费和请求趋势稳定后，V4 可以提供：

1. 采购容量耗尽时间预测。
2. 月度收入、成本和毛利预测。
3. 不同请求增长情景下的采购需求。
4. 调整价格或倍率后的毛利模拟。
5. 渠道路由占比变化后的成本模拟。

预测结果不能进入正式财务口径，必须标记为预测或模拟。

## 11. V4 不做事项

V4 默认不做：

1. 无人确认的自动涨价或降价。
2. 无人确认的自动停用渠道。
3. 用预测值覆盖正式财务数据。
4. 在 Router 内建设完整会计总账。
5. 把用户充值流水当作请求计费收入。
6. 把 Billing 服务余额当作采购成本。

## 12. V4 启动条件

启动 V4 前必须满足：

1. V3 采购事件和采购批次链路稳定。
2. 请求成本可以追溯到采购事实。
3. 成本覆盖状态可信。
4. 总览、利润、采购的基础下钻闭环完成。
5. 财务筛选上下文可以通过 URL 恢复。
6. 财务异常已有稳定类型和严重程度定义。
7. 数据量和查询性能可以支持对象级详情和周期对比。
